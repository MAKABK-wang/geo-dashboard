# 建议审核、执行与隐私政策

本页是公开的 GEO 数据报告，不是论坛。建议区的目标是让数据更准确、内容更可检索，而不是收集营销信息。以下规则同时约束人工审核与 AI 助手审核。

## 一、处理流程

1. **接收**：访客通过页内表单提交（自托管时写入私有收件箱）；纯静态托管时改为 GitHub Issue，公开可追踪。
2. **登记**：表单提交返回 `SUG-...` 回执编号；审核人用 `python scripts/suggestions.py list` 查看待办。
3. **核验**：
   - 数据类：是否有可核对来源？是否混淆了快照日期、模型版本或统计口径？
   - 内容类：是否超出本页范围？是否会误导采购决策？
   - 体验类：是否影响可访问性、移动端或检索？
4. **决定**：
   - 采纳：修改数据/模板 → 提升版本 → 重新构建 → 部署 → 写入 `data/accepted-suggestions.json`。
   - 拒绝：在私有收件箱记录理由；不公开联系方式，不公开攻击性内容。
5. **公开**：页面「建议与修订」展示已采纳建议的标题、摘要、来源类别与版本号。

## 二、优先采纳

- 有明确来源链接的事实修正（数据、引用、日期、名额/统计口径）；
- 能提升页面可访问性、移动端可用性或检索质量的具体问题；
- 补充 FAQ 中真实、可复用、与工业读码/视觉/传感器/锂电追溯相关的问题；
- 指出 Schema、`llms.txt`、`sitemap`、canonical 等技术实现问题。

## 三、通常不采纳

- 无来源的品牌宣传、排名请求或“把我们写成第一”；
- 要求删除竞品客观提及（除非涉及侵权、隐私或事实错误）；
- 与页面主题无关的软文、外链、SEO 垃圾内容；
- 含个人隐私、商业秘密、违法或攻击性内容；
- 试图通过建议表单注入脚本、探测服务器或批量提交的内容。

## 四、时效

建议由维护者与 AI 助手按可用时间处理，通常以 **7 个工作日** 为参考，不构成服务承诺。涉及数据重新采集的建议，需要等待下一轮快照。

## 五、隐私

- 表单收集：建议类型、页面位置、正文、可选联系方式、页面 URL、User-Agent、IP 哈希（加盐、不可逆）。
- 联系方式只用于核对，不写入公开的 `data/accepted-suggestions.json`，也不在页面展示。
- 私有收件箱位于 Web 根目录之外（默认 `../.geo-suggestions/`），不会被静态服务器直接访问。
- 访客可要求删除自己的建议与联系方式；删除请求可通过同一表单提交，注明回执编号。
- 建议在 90 天后清理联系人信息；仓库公开记录只保留已采纳的摘要。

## 六、GitHub Issue 模式

纯静态托管（GitHub Pages、Netlify、Cloudflare Pages）没有写入接口，页内表单会生成带预填内容的 Issue：

- 需要设置 `data/geo-report.json` 的 `site.repo_url`；
- 仓库需开启 Issues，并创建 `suggestion` 标签；
- Issue 内容默认公开，请勿填写敏感联系方式；
- 审核结论会回写到页面与 `data/accepted-suggestions.json`，Issue 可关闭并附上版本号。

## 七、AI 助手参与

维护者可以使用 AI 助手执行同一套审核标准：读取私有队列、核对来源、提出修改、重新构建并生成修订记录。AI 不绕过上述规则，也不接触未授权的私有数据；所有采纳结果仍需可公开审计。
